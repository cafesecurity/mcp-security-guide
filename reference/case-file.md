Real cases behind the controls in this guide. Several are research demonstrations rather than breaches, and are marked as such. No case here is attributed to any group or country. Newest first.

Anthropic called this expected behaviour and said sanitising is the developer's job. OX also got a harmless test package accepted by 9 of 11 registries. | A launch command is code. Both fixed before Check Point's write-up. | A cloned repository can configure your tools. A malicious server's OAuth endpoint URL was passed unsanitised to code that opens a browser. Full command execution on Windows; limited execution of programs on macOS and Linux. | Every string from a server is untrusted, including URLs in metadata. Test project, dummy data. | One agent held all three letters. Give agents the narrowest key, and keep readers of outsiders' text away from write tools. | [Threat model](../guide/01-threat-model.md) |

Fixed in 0.14.1. | Bind to 127.0.0.1, require a token even locally, and check `Host` and `Origin`. | [Build](../guide/03-build.md), [Deploy and operate](../guide/06-deploy-operate.md) |
| Jun 2025 | [Asana MCP cross-tenant exposure](https://www.bleepingcomputer.com/news/security/asana-warns-mcp-ai-feature-exposed-customer-data-to-other-orgs/) | A logic bug present since launch on 1 May let some data from one organisation appear for another. Found 4 June, about 1,000 customers affected, server offline until 17 June. | Check tenant on every request and test isolation in CI. Know how you would take the server offline. | [Test](../guide/04-test.md), [Incident and retire](../guide/08-incident-retire.md) |
| Jun 2025 (exercise) | [Jira Service Management prompt injection](https://www.catonetworks.com/blog/cato-ctrl-poc-attack-targeting-atlassians-mcp/) | Cato Networks showed a support ticket carrying instructions that, when an engineer's agent processed it with Atlassian's MCP tools, collected ticket details and posted them back where the outsider could read them. ATLAS AML.CS0039. | Results are outsiders' text. Tag them and restrict what can run after them. | [Design](../guide/02-design.md) |
| May 2025 (demonstration) | [GitHub toxic agent flow](https://invariantlabs.ai/blog/mcp-github-vulnerability) | Invariant Labs: a malicious public issue led an agent with an all-repositories token to leak private repository details, including a salary and an address, in a public pull request. ## Commonly retold, actually

- **"Thousands installed and contributed to postmark-mcp."** It was one impostor's package with about 1,643 downloads, copied from Postmark's official code.
- **"mcp-remote let attackers chain commands with a semicolon on Unix."** No shell is involved on macOS or Linux. The full exploit worked on Windows.
- **"Replit's database wipe was an MCP incident."** It was Replit's own agent on Replit's own database. No MCP server was involved.
- **"EchoLeak was an MCP attack."** It was indirect prompt injection in Microsoft 365 Copilot (CVE-2025-32711). No MCP was involved.
- **"The Supabase MCP breach."** It was a controlled demonstration on test data.
- **"A GitHub MCP agent deleted a branch after reading a planted SECURITY.md."** No such incident is documented.
- **"Resource indicators bind tokens to a server."** Only if the authorisation server honours them. The server's own audience check is what protects you.
- **"MCP sessions are long-lived and stateful."** True before the 2026-07-28 spec, which removed sessions.
- **"A study of 9,000 MCP servers found over half were developer tools."** The study ([arXiv 2512.03775](https://arxiv.org/abs/2512.03775)) measured cryptographic misuse. Over half of the misuses it found were in developer-tool and data-science servers, not over half of all servers. An earlier version of this guide, and the first video in the series, repeated the wrong figure.
